# 小圆点旋转位置验证

日期：2026-09-21。版本：2.0.8(Beta) debug。

## 修复内容

原来的换算把悬浮窗可用区域坐标当成屏幕物理坐标，并用扣除部分系统栏后的屏幕尺寸旋转。现在先加入悬浮窗区域的左、上偏移，在完整屏幕坐标中旋转，再转换为新方向的悬浮窗坐标。Android 11 及以上使用 WindowMetrics 的系统栏和刘海边距，并使悬浮窗使用相同的边距规则。

保留用户最后拖动确定的物理锚点，旋转时不把临时边界限制覆盖到锚点上。展开面板和隐藏小圆点期间也保留这个位置，避免反复旋转造成累积偏移。

若原物理位置被新方向的状态栏、导航栏或刘海占用，小圆点会限制在可点击区域内；转回原方向后恢复原位置。此修复针对控制器存活期间的屏幕旋转，不新增跨进程重启的方向记忆。

API 参考：[Display](https://developer.android.com/reference/android/view/Display)、[WindowManager.LayoutParams](https://developer.android.com/reference/android/view/WindowManager.LayoutParams)。

## 验证

- `assembleDebug`、`assembleDebugAndroidTest`、`lintDebug` 通过。
- 8 项坐标单元测试通过，覆盖四边停靠、所有旋转方向组合、状态栏/侧边导航栏偏移、固定锚点。
- Android 16.1 / API 36.1 手机模拟器：FloatingControlLayerTest 全部 10 项通过。
- Android 14 / API 34 平板模拟器：FloatingControlLayerTest 全部 10 项通过。
- 新的旋转设备测试覆盖：90°后沿边缘的物理坐标、转回后完整坐标、面板展开时反向旋转、角落双向连续旋转、隐藏期间旋转后恢复。
- 原有展开、拖动、图片覆盖层次、确认按钮、精确控制面板和窗口销毁测试保留并通过。

设备测试直接创建真实控制器窗口，使用 UiAutomation 旋转屏幕，然后调用与通知服务相同的配置更新入口。测试不覆盖通知服务回调的实际交付时机，也不代表三星、华为等厂商真机结果。

初次启动模拟器时曾遇到旧快照图形崩溃，改用冷启动和软件渲染。首次在系统设置界面运行出现触摸测试失败；API 34 最终在时钟界面运行通过，API 36.1 复查通过。两个最终完整结果分别保存于本目录。

本机 Gradle 单元测试执行器在含中文的路径下出现测试类加载失败；编译后的相同测试使用 JUnitCore 和相对类路径运行通过。未修改项目构建配置来绕过该环境问题。
